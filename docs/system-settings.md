# 系统配置

管理后台的“系统配置”支持即时更新诊断设置，配置存储在 SQLite
`app_config` 的 `system-diagnostics-v1` 中。仅管理员可访问
`GET/PUT /admin/api/system-config`，不返回凭据或文件路径。

首次保存前使用启动参数和环境变量；保存后 WebUI 配置优先，重启后保留。
配置在内存中读取，不会逐请求或逐 token 查询数据库。

## 第一阶段设置

“配额百分比显示口径”可选剩余（默认）或已用，统一配额页与请求追踪的
百分比文字及进度条。保留真实剩余额度作为告警颜色依据；原始金额、计数、
重置时间、路由策略与历史数据不变。旧配置自动补入默认值。

| 设置         | 推荐    | 影响                                                               |
| ------------ | ------- | ------------------------------------------------------------------ |
| 日志级别     | info    | 同时控制控制台和文件输出，warn 仍保留错误与警告                    |
| 详细性能指标 | 开      | 关闭后新请求不采集新增分段指标，不改变基础用量、TPS 和原有 TTFT    |
| 详细内存日志 | 关      | 控制逐请求检查点输出，不关闭内存压力 watchdog                      |
| 请求 dump    | 关      | 开启需要敏感数据确认，请求与失败上游请求在脱敏后写盘               |
| 临时调试时长 | 15 分钟 | 1–120 分钟，到期关闭 dump 和详细内存日志，并将 debug 日志降为 info |

详细性能指标在请求开始时决定是否采集，在途请求保持原有状态。
日志和 dump 开关在后续调用时生效；已经开始的写盘不会被撤销。
重启不会延长调试期限。关闭 dump 不删除已有文件，需按数据治理要求清理。
新写入的请求和失败上游 dump 会遮盖认证头、凭证字段、文本中的认证信息、JSON 字符串内的工具凭证及内嵌媒体。普通提示词、代码和工具参数仍保留用于排障，因此开关仍要求敏感数据确认。无法解析或超限的入站正文会省略；上游字段先脱敏再按字节截断。此改动不会重写历史 dump，也不会改变发往上游的请求。
已有环境变量启用的诊断在首次 WebUI 保存前保持兼容，不强行设置期限。

## 性能结论

收益主要来自减少原始请求体读取、JSON 序列化、详细日志格式化和磁盘 I/O。
大历史、多并发、磁盘较慢时尤其值得关闭 dump。
仅关闭日志输出不能消除所有调用方提前构造参数的成本；热循环仍需显式守卫。
详细性能指标主要是时间戳和少量状态，部分 SSE 首文本识别还涉及 JSON 解析。
基础统计、追踪结束状态、错误告警不应跟随总调试开关关闭。
不能据此承诺显著 TPS 提升或固定首字延迟降幅，需要真实负载对照测量。

## 后续分组

- 日志管理：轮转大小、保留天数、dump 采样率与总磁盘预算；先明确清理与在途写入语义。
- 健康监控：watchdog 间隔和告警阈值；保留默认告警，避免错误配置导致监控盲区。
- 运行参数：端口、监听地址、代理属于需要重启的部署配置，不伪装成即时生效。
- 安全、限流和路由保持各自专用页面；密钥、密码和任意文件路径不放进诊断开关。

当前日志轮转与保留天数仍使用原有环境变量，避免不受控的热更新清理。
