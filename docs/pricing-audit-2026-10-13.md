# copilot-api 价格计算审计（2026-10-13）

## 结论与正确取价规则

计费身份是“上游渠道 + 该渠道完整模型 ID”。模型作者、兼容协议、公开别名和订阅渠道不是同一个概念。例如 OpenRouter 的 `xai/grok-*` 必须查询 OpenRouter 模型表，不能因为 `xai/` 是作者前缀就改用 xAI API 单价。

价格查询顺序：公开模型的显式手工覆盖（零价也有效），实际连接的完整上游型号和渠道目录，按渠道保存的离线快照；最终无法确认的报价保持 unmatched。无渠道的作者型号优先原厂，同名的未知型号只有各渠道报价一致时才能回退。旧静态表中的 Copilot 校准价不能给其他明确渠道补价。

## JSON 的含义

| 字段                                       | 正确解释                                                                    |
| ------------------------------------------ | --------------------------------------------------------------------------- |
| 外层 provider key                          | 计费渠道，不等于模型作者                                                    |
| `provider.api`                             | 上游 API 地址，用于普通兼容连接的渠道识别；匹配 origin 和路径，歧义不猜     |
| `models` 的 key                            | 渠道完整型号；优先于 `model.id`、尾部别名和点号/横线别名                    |
| `cost.input/output/cache_read/cache_write` | USD / 百万 token；内部换算成每千 token 要除以 1000                          |
| 缺失 cache rate                            | 没有声明缓存折扣；保守按输入价估算，不能当作免费                            |
| 显式 `0`                                   | 有效免费价格；不能被缺省值或防呆逻辑覆盖                                    |
| `cost.tiers[].tier`                        | 按实际 `type=context` 和 `size` 选档；保留全部上下文档位                    |
| `context_over_200k`                        | 兼容旧字段；有现代 `tiers` 时使用现代阈值，不能仅凭字段名字覆盖 272K 等阈值 |

单次 prompt 总量 = 普通输入 + 缓存读取 + 缓存写入。超过对应阈值后整轮按高档单价计算，而不是只算超额部分。多轮搜索逐轮计算，不能给合并总量再次套阶梯。档位未单独声明的费率继承基础费率；没有声明缓存价时按该档输入价估算。

Claude 缓存写入的 `cache_creation` 明确区分五分钟和一小时。一小时使用当轮有效输入价的 2 倍，剩余缓存写入使用该档 `cache_write`。TTL 信息穿过协议转换和搜索轮次，不额外加到 total token。

## 已修复的问题

| 问题                                              | 修复                                                              |
| ------------------------------------------------- | ----------------------------------------------------------------- |
| 同渠道 `tee/model` 的尾部覆盖 `model` 原价        | 先建完整 key，后加无歧义别名，缺价的完整 key 也不会被覆盖         |
| 指定渠道未找到仍拿其他渠道价格                    | 显式渠道查询失败保持 unmatched                                    |
| 普遍剥离 mini、nano、max、fast                    | 只保留显式 Windsurf 的已知 SKU 估算规则                           |
| 子串匹配把未知型号套成基础价                      | 内置表只接受完整匹配和受限日期快照                                |
| 缺失缓存费率变成 0                                | 缺失使用输入价，显式 0 仍免费                                     |
| 兼容协议被当作供应商、公开别名被用来取价          | 连接端点识别渠道，并按实际上游型号定价；界面和记账共用解析器      |
| Devin SWE 单价覆盖无关渠道                        | 限定 Devin 产品的报价作用范围                                     |
| TTL 转换丢失，一小时写入被按五分钟计费            | IR 和所有相关协议/记账路径保留一小时数量                          |
| Responses 缓存写入固定为 0                        | 从兼容扩展提取写入数量并从总 prompt 中扣除，避免漏计或重复计费    |
| 手工高档全零被忽略                                | 保留显式免费档位，缺失字段逐项继承                                |
| 离线使用混合渠道旧价并丢失阶梯                    | 17 个内置渠道的快照保留出处、完整型号、缓存和阶梯，复用在线解析器 |
| 无效价格造成负数或 NaN                            | 目录报价校验有限非负数；非法模型报价不进入索引                    |
| 历史重算忽略阶梯、Fast、TTL 或把 unmatched 写成 0 | 缺少足够元数据的行跳过，保留原费用；明确输出跳过数                |

## 实际限制

未知或共享端点可能无法唯一匹配渠道，需要手工定价；订阅账户这里记录 API 等价估值，不是订阅额度扣减或实际账单。目录没有声明的缓存折扣、图片/音频/工具费用、历史调价及私人折扣不能仅靠文本 token 推断。

旧 usage 行只保留合并 token 和费用，不保留逐轮上下文、TTL、服务档位。不能可靠重算的行必须保留原数值。本次未修改真实用量数据库、未部署或重启正在运行的服务。
